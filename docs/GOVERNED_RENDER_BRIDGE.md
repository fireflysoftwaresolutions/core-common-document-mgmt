# Governed render bridge (unactivated component)

The existing `DocumentPort` has a reactive governed overload. Its existing `DocumentIssuance` implementation now lives in `io.fireflysoftware.documents.impl`; applications importing that implementation directly must update the import. Legacy synchronous issuance remains separate. Main explicitly imports `GovernedDocumentConfiguration`, and Web declares its normal Generation dependency; Generation declares Core and the framework validators dependencies. No generated SDK or specification is edited.

`firefly.documents.governed.enabled` defaults to false. Enabling it requires a current snapshot service, an explicit `DocumentRenderProfiles` registry, an actual `DocumentGenerationEventSource`, the concrete audited `SpringDataDocumentGenerationCommitService`, and the shared `documentGenerationClock` / `documentGenerationNanos` time-source beans. It disables the legacy adapter configuration if that configuration is separately imported. No catalog, tenant, actor, token, admission, event, profile, or storage success is supplied as a fallback. The event source must obtain genuine actor/policy/native issuance authority; an audit event is not itself that authority. The commit service still requires current native admission and an exact same-root immutable audit append before business reads/writes.

The current owner reader uses genuine Config/Masters SDK APIs, fresh call-local authentication, exact allowed HTTPS origins, and the same original caller budget. Owner calls occur outside SQL. After CURRENT/layout/source retrieval it retrieves each declared immutable notice revision in order. The snapshot validates all notice references, lifecycle, locale, source/content/schema/style hashes and raw canonical strings. Issuer presentation is copied only from the matching Config CURRENT definition with `OWNER_ATTESTED` provenance. This is authenticated owner attestation, not a claim of local Config private canonical digest verification. It preserves display name, email, tenant name, color/footer metadata and branding identity without inventing an address.

The governed renderer extends the existing FreeMarker adapter. It accepts only a deployment capability pinning the exact reviewed source and layout references plus the exact owner output profile code/version/media/manifest digest. The capability explicitly declares `REVIEWED_OWNER_SOURCE_AND_LAYOUT_INLINE`. Real FreeMarker conditions, lists and macros remain available. The data model exposes primitive facts, owner presentation, ordered notice records, exact source and layout data. It does not use `DocumentModel`, `KitStationery`, a classpath template fallback, or locale fallback. Facts must satisfy the actual offline Draft 2020-12 owner schema. Java/API access and class construction are disabled; no template loader is installed. Owner templates determine notice placement and must include their required disclosures; these unit vectors are not an approved product document design.

Input/output and interpreted-element caps plus inherited budget checks are safeguards, not a hard CPU/heap sandbox for arbitrary FreeMarker builtins or schema expressions. General/untrusted templates require an isolated-worker capability that this component does not provide. There is no default registry or generic safe-template flag. A deployment review must bind actual approved source/layout revisions, disclosure rendering and permitted profile behavior before activation.

`logoUrl` remains owner metadata. The renderer never fetches it, never synthesizes an asset digest, and does not place it in the render model. A profile requiring a logo refuses because a safe immutable/current-bound asset capability is not implemented. Other remote assets, provider rendering/browser acceptance, PDF/layout/design acceptance and signing are not qualified here.

The governed overload retains the original budget identity across snapshot, event and commit boundaries and applies an initial five-second delivery envelope without renewing authority. It renders first, obtains the externally bound event for the exact bytes, and passes that request to the existing audited owning transaction. The result is only local `PENDING_PROVIDER`; no blob call or compensating delete is made by this branch. Exact immutable issuer presentation and ordered notice snapshots join the whole intent when present. Reference-only snapshots preserve their previous JSON shape. The metadata CHECK hashes the full intent, native admission/context and all four local rows bind the same digest, and the genuine audit hook verifies that digest/event in the same physical writer session. No SQL or role changes are included; this is source inspection, not a native installation or durability claim.

Remaining prerequisites: a supported governed owner HTTP/OpenAPI entrypoint and genuine regenerated client invocation; actual configured token delegation and event/native admission issuer; reviewed exact profile/asset capabilities; optional document schema plus original audit deployment/native qualification; actual owning transaction/current/restart/recovery proof; external provider outbox worker/recovery; isolated general-template execution; and realistic product/financial/legal/document-layout acceptance. Internal Java/context tests do not qualify production Web/Main behavior or a complete document journey.
