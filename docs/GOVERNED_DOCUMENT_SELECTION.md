# Governed document selection prerequisite

This source slice extends the existing document owner with exact Masters source/layout selection and Configuration issuer CURRENT evidence. It does not activate a controller, renderer, storage writer, provider, or a Spring bean. The existing generation paths and Firefly stationery remain separate legacy behavior; they are not a fallback for this governed path.

## Owner reads and snapshots

`DocumentCurrentSnapshotService` accepts an explicit resource tenant and product definition root, product, revision, publication, and definition digest. The supported purpose is the existing `DEPOSIT_ACCOUNT_ENROLLMENT`. Masters references identify immutable source and layout revision UUIDs, their identical exact opaque owner version, and their respective source/definition digests. Issuer references identify the Configuration publication UUID, positive numeric revision, and definition digest.

The genuine generated SDK adapter calls Masters CURRENT, exact layout, and exact source revision, then Configuration issuer CURRENT. Its configured HTTPS origins and allowed token issuers are explicit. A mandatory trusted `DocumentOwnerTokenProvider` must establish real actor/delegation issuer, audience, resource tenant, and expiry; this source supplies no token-authority implementation. Each observation creates private call-local generated API clients and configures only the actual named bearer scheme. No shared SDK authentication is mutated. Owner HTTP refuses a reactive transaction context and retains the same original operation budget across token acquisition and all four calls.

The validator checks the complete target tuple, publication lifecycle, locale, owner version, immutable source identity and content/schema/style/source byte hashes. It hashes the supplied layout canonical bytes with the existing owner frame and compares the parsed bytes with the typed definition. It does not reimplement either owner's canonical JSON algorithm. The returned snapshot contains immutable strings rather than mutable generated DTOs.

The whole owner read is bounded by the earlier of the original remaining technical budget and five seconds; a stalled owner cannot extend that ingress wait. Both owner CURRENT windows must be positive and at most 5,000 milliseconds. Delivery retains the earlier original technical budget, delegation expiry, both owner effective caps, and the initial five-second limit. Masters provenance is explicitly `EFFECTIVE_ONLY`; no native deadline is invented from its effective cap. Configuration's actual native deadline remains separate evidence.

The issuer snapshot currently retains the exact reference and primitive generation/window evidence. It does not expose a renderable issuer definition or claim `LOCAL_CANONICAL_DIGEST_VERIFIED` for Configuration's private wire codec. A genuinely authenticated and qualified owner response can support a future explicit `OWNER_ATTESTED` definition snapshot. A public owner integrity envelope would additionally support portable independent byte verification; absence of that envelope alone does not invalidate an authenticated owner DTO. This source does not qualify live owner transport or supply the missing real delegation adapter.

## Storage remains unavailable

`DocumentGenerationStorage` describes the future owning-root boundary. Exact current admission, assigned-ID mapped document/immutable metadata/issuance-state operations, and the exact immutable audit append must share the same genuine bounded root and transaction resources. An audit denial must roll back the local business effect. A renderer result or caller-supplied actor, tenant, snapshot, audit event, or budget is not authority.

Public V1–V3 do not contain that exact-reference aggregate or its qualified native current/audit admission. `UnmigratedDocumentGenerationStorage` therefore always refuses, including empty-success attempts. It does not write legacy metadata, choose an `openplatform` tenant, emulate an aggregate, or restore historical private binding/signature migrations. A deliberate new aggregate migration, real Spring Data operations, role/RLS/integrity catalogue, same-root audit adoption, and native atomicity/restart qualification are required before storage can succeed.

External blob or document providers require durable intent/outbox/recovery and explicit adapters. Their side effects cannot be made atomic by SQL alone. The existing sandbox templates and assets are not product, legal, financial, signing, or production generation acceptance.
