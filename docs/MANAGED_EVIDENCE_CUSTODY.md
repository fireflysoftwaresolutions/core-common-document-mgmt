# Managed evidence custody

`POST /api/v1/managed-document-evidence/applications/{applicationId}/actions/{actionId}` stores actual evidence bytes, document metadata, immutable custody, and the canonical audit event/outbox in one bounded Document owner transaction. The body carries the same application/action, the signed party, filename, media type, document classification code, and base64 content. The server independently binds the party to the verified HUMAN caller and checks current policy; these body identifiers do not confer authority.

Content contains 1 through 2,097,152 decoded bytes. The OpenAPI base64 string bound is 4 through 2,796,204 characters and the JSON envelope is limited to 3 MiB. New storage returns 201, exact original-action/content replay returns 200, and changed intent conflicts with 409. Typed 503 outcomes distinguish refusal before mutation dispatch or after proven rollback (`REFUSED`), uncertain completion (`OUTCOME_UNKNOWN`), and a committed result whose response is unavailable (`COMMITTED_RESPONSE_UNAVAILABLE`). Recovery retains the original action and exact original input. Generic response caching is disabled so a repeated HTTP key cannot bypass current authorization.

The owner uses mapped Spring Data operations and native PostgreSQL enum codecs. Bytes live in `document_evidence.content`; immutable custody lives in `document_evidence.custody`. The legacy document row records `DATABASE`, `RESTRICTED`, and `UNDER_REVIEW`, with an owner-generated `document-evidence/<documentId>` path. Storage completion does not verify the evidence or associate it with a loan. The existing ECM provider ports remain available for their existing content flows.

## Scoped receipt and content reads

`GET /api/v1/managed-document-evidence/applications/{applicationId}/actions/{actionId}` observes the existing original receipt. The same path with `/content` returns actual stored bytes as `application/octet-stream`, with the actual length and `X-Evidence-Content-SHA256`. Both responses use `Cache-Control: no-store`. Consumers must independently hash the returned bytes and compare the full original receipt; the digest header or metadata alone is not content readback.

Each read requires a current verified HUMAN caller with `document:evidence:read`, the original signed party, current resource binding, and current policy evaluation. An upload scope does not grant read access. The owner scopes mapped reads by tenant, application, party, and original action, verifies actual content and complete metadata, and proves the original completed canonical event/outbox through the published native accessor. It creates no business row or audit event. Its technical audit context still uses a finite owned transaction and the existing writer login; it does not claim a SQL read-only transaction.

The owner returns 200 only after those checks. Authentication/authorization refusals remain 401/403. Typed 503 `OBSERVATION_UNAVAILABLE` means the current observation cannot be supplied; no upload or replacement action was dispatched. Recovery uses the same original action. A provider setup failure has this same unavailable envelope and cannot dispatch a read. Reads do not use the legacy external ECM download port for the managed bytea path.

It requires explicit issuer, audience, allowed-client-id, platform-tenant, resource-tenant-id, binding-id, binding-version, binding-digest, and not-after properties under `document.evidence.upload`. Supply the genuine global resource-server decoder/projection and one current `PolicyEvaluationPort`. The business feature flag does not disable the global receiver. Run V10 as the existing `documents` owner. The canonical audit owner must grant `firefly_audit_require_completed(UUID,UUID,BIGINT,TEXT,BOOLEAN)` execution to the new guard and the canonical runtime writer. The runtime writer receives SELECT/INSERT for the managed business graph; it receives no private-schema or business UPDATE/DELETE/TRUNCATE authority. The installer verifies the expected published function and removes its temporary private trigger access.

The original finite five-second authority window covers admission, the owned transaction, and post-commit revalidation. SQL independently verifies actual content digest/length, the complete metadata graph, and the exact completed canonical audit tuple. Immutable guards reject managed metadata/custody mutation, deletion, and truncation. Loan association failure must retain truthful document custody; deleting content is not an invented compensation.
